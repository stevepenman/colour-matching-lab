# Publication review

The portfolio directory is a separate derivative. Existing source files and original records outside it were preserved. Only the main GUI source was used as a starting point; supporting modules, documentation, tests, workflow and synthetic examples were prepared for this copy. No existing Git history was copied.

Excluded material includes organisation branding, original product lists and measurement histories, the previous colour CSV and generator, local environments, caches and prior documentation. The replacement reference library is generated from an HSV grid and neutral RGB levels with fictional labels; initial product names are explicitly fictional. No production data or original report is bundled.

Organisation-specific comments, names, asset references and unused password-gate code were removed. The copy requires no passwords, service credentials or contact information. It contains no machine identifiers or service endpoints. Camera access requires an explicit local webcam option. No machine integration, email or external service client is included.

The GUI changes are visible in code: a connected preview, a layout-based main page, centre-frame sampling instead of random input and a blocking delay, a shared validated matching core, truthful spatial-averaging semantics and string-preserving product IDs. Unsupported camera-platform autodetection was removed. The calibration page explains its unimplemented status.

Review covered filenames, all publication text, configuration, source, comments and synthetic data, plus visual inspection of the generated screenshot. The final checks included a private deny-term search and heuristic scans for credentials, key material, personal emails, private IPv4 ranges and workstation paths. Specific removed identifiers are deliberately not reproduced here. No finding was identified in the reviewed publication files; this is not a guarantee that every kind of sensitive information can be detected automatically.

`scripts/audit_publication.py` enforces the reviewed file inventory and repeatable generic checks. It skips the fresh Git metadata and ignored local environments/runtime directories. The allowlist must be consciously updated when adding new public files. `.gitignore` reduces accidental inclusion; it does not protect a file already tracked by Git or make `git add -f` safe.

Review the Git staging list before upload. Publish only this directory's reviewed files. Do not upload the parent workspace, local environment, runtime captures or new workplace records.
